Project Goal

사용자 경험, 이벤트 신뢰성, 운영 안전성을 함께 설계

01

소셜 피드 경험

팔로우 피드, 공개 범위, 댓글·대댓글, 컬렉션·다이어리와 독립 To-do를 연결하고 모바일 파일 선택과 뒤로 가기 동작을 보완했습니다.

02

신뢰할 수 있는 실시간성

채팅·알림 이벤트를 MySQL outbox에 먼저 기록하고 Kafka로 전달하며, WebRTC 음성 통화는 Redis 상태 머신과 STUN/TURN으로 연결합니다.

03

안전한 운영 제어

신고·상소, 장애·접속 추적, outbox 상태에 비공개 파일 보관함과 GitHub 변경 내역을 더하고 관리자 권한을 서버에서 검증합니다.

Implementation Highlights

장애가 발생해도 복구 가능하도록 설계한 구현 포인트

Outbox 발행 복구

MySQL에 이벤트를 남기고 커밋 후 발행합니다. 실패 시 지수 백오프와 적응형 poll로 재시도하고, 한도 초과 이벤트는 dead letter로 남깁니다.

음성 통화 수명주기

Redis Lua로 1인 1통화와 상태 전이를 원자적으로 제어하고, 세션 연결 해제·TTL·관리자 액션으로 남은 통화를 종료합니다.

운영 가시성

시스템 자원, outbox·dead letter, 이미지 정리 큐, 활성 로그인 IP·지역을 표시하고 장애 IP와 반복 횟수를 확인 처리합니다.

Admin-only S3 File Storage

파일 형식은 열고, 저장소 접근은 관리자로 제한

Authorization

화면과 API의 권한 검사

실행 파일·압축 파일·확장자 없는 파일을 업로드합니다. 목록과 다운로드도 ADMIN 권한을 검사하고 업로드에는 CSRF 검증을 적용합니다.

Private Bucket

이미지와 관리자 파일 분리

관리자 전용 비공개 버킷의 공개 접근 차단 4개 항목을 검사합니다. 공개·서명 URL 대신 서버를 거쳐 첨부파일 스트림을 전달합니다.

Minimal Metadata

저장 위치 중복 정보 제거

DB에는 ID·원본 이름·크기·업로더·생성 시각만 저장합니다. 버킷은 설정값, 객체 키는 admin-files/{id}를 사용하며 버전 관리는 쓰지 않습니다.

Failure Handling

용량 검증과 실패 정리

Spring 공통 업로드 제한을 적용하고 파일 스트림을 S3로 전달합니다. DB 저장이 실패하면 객체 삭제를 시도하며, 파일을 실행하거나 압축 해제하지 않습니다.

Domain Rules

기능을 나열하는 데서 멈추지 않고 정책과 예외 처리를 코드에 반영

Account

상품·정산 정책

입출금·예금·적금별 금리와 만기를 관리하고, 적금 자동이체 및 실패 알림, 해지 시 원금·이자 정산과 거래 취소를 검증합니다.

Safety

신고·제재·상소

중복 신고를 차단하고 경고·일시정지·차단 이력을 남깁니다. 회원은 본인 제재를 선택해 상소하고 관리자는 상태별로 검토합니다.

Audio Call

통화 동시성 제어

1:1 방 참여자만 통화하고, 통화를 시작하거나 받은 기기의 세션만 SDP·ICE·종료 신호를 보낼 수 있도록 검증합니다.

Event Delivery

저장과 전달의 순서

알림과 outbox를 같은 트랜잭션에 저장하고, 채팅은 Consumer의 MySQL 커밋을 마친 결과만 WebSocket으로 전달합니다.

Admin Operations

장애, 로그인 접속, 코드 변경을 운영 화면에서 확인

GitHub 변경 내역

커밋과 Push 활동을 구분해 조회합니다. 페이지네이션, 60초 서버 캐시와 API 호출 제한 대기로 외부 요청을 줄이며 토큰은 서버에만 둡니다.

접속·장애 추적

유효한 Refresh Token의 접속 IP·지역과 서버 장애의 IP·반복 횟수를 확인합니다. 신고·상소 처리와 통화 강제 종료도 관리자 영역에 모았습니다.

채팅방 조회 경험

관리자 채팅방 목록의 모바일 스크롤을 보완했습니다. 방 참여자·사진 갤러리 API는 참여 여부를 검사하고 사진은 커서로 나눠 조회합니다.

GitHub 기록은 변경 내역 조회이며 배포 완료 이력이나 영구 감사 로그가 아닙니다. 사진 갤러리는 삭제·검열·본인에게 숨긴 메시지를 제외하고, 방을 나가면 조회를 차단합니다. 메뉴 노출뿐 아니라 페이지·API·서비스의 권한 검사로 운영 기능을 보호합니다.

Design & Iteration

기능 추가와 함께 책임 경계와 예외 흐름을 정리

Layering

Controller–Facade–Service

요청·인증 확인, 서비스 호출과 응답 조합, 도메인 로직의 역할을 나눴습니다. 계좌·관리자 등 기존 API도 Facade 중심으로 정리했습니다.

Personal To-do

일기에서 분리한 개인 할 일

작성·수정·삭제와 완료 상태 필터를 지원합니다. 로그인 회원의 소유권으로 조회하고 관리자도 다른 회원의 할 일에 접근할 수 없습니다.

Token Lifecycle

브라우저 토큰 교체와 폐기

재로그인 시 해당 브라우저의 이전 Refresh Token만 폐기하고 다른 기기는 유지합니다. 로그아웃에서도 요청 중 교체된 토큰을 추적해 정리합니다.

Mobile UX

공통 업로드와 뒤로 가기

모바일 이미지 선택 값을 보존해 multipart를 다시 구성하고 업로드 처리를 공통화했습니다. 페이지 복귀와 긴 관리자 테이블의 스크롤도 보완했습니다.

Service Surface

화면, REST API, WebSocket, SSE가 함께 동작하는 서비스 표면

사용자 화면

피드·채팅·통화·다이어리·To-do와 계좌를 제공하고, 관리자 영역에 파일 보관함과 GitHub 변경 내역을 추가했습니다.

/board/main · /chat/chatList · /todo · /admin/files · /admin/github

REST API

웹·모바일은 도메인 API를 공유합니다. 모바일 토큰 발급·회전·OAuth 교환과 개인 할 일·관리자 파일 API의 권한을 각각 확인합니다.

/api/mobile/auth/** · /api/todo · /api/admin/files/** · /api/admin/github/**

Realtime

SockJS/STOMP 메시지·통화 시그널링, 사용자 전용 통화 큐, SSE 알림, REST ICE 설정을 함께 제공합니다.

/ws/chat · /api/chat/message/send · /api/audio/signal · /api/notification/stream
