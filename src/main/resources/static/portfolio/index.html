Project Goal

사용자 경험, 이벤트 신뢰성, 운영 안전성을 함께 설계

01

소셜 피드 경험

팔로우 피드, 프로필 공개 범위, 좋아요, 댓글·대댓글, 컬렉션과 다이어리를 하나의 사용자 활동 흐름으로 연결했습니다.

02

신뢰할 수 있는 실시간성

채팅·알림 이벤트를 MySQL outbox에 먼저 기록하고 Kafka로 전달하며, WebRTC 음성 통화는 Redis 상태 머신과 STUN/TURN으로 연결합니다.

03

안전한 운영 제어

신고 제재와 상소, 금칙어 누적 정책, 장애 IP·발생 횟수, outbox 대기·dead letter, 통화 강제 종료를 관리자 화면에서 관리합니다.

Core Features

클라이언트 경험부터 운영 워크플로까지 하나의 계정으로 연결

피드·관계·기록

채팅·알림

REST/STOMP 채팅, outbox 기반 Kafka 전달, 방별 배치 저장, 이미지·읽음 상태, SSE 알림, 1:1 WebRTC 음성 통화

계좌·안전·관리

입출금·예금·적금, 이자·자동이체·중도해지, 신고 제재·상소, 금칙어 승인, 장애 추적과 통화 강제 종료

Implementation Highlights

장애가 발생해도 복구 가능하도록 설계한 구현 포인트

Outbox 전달 보장

Kafka보다 MySQL에 이벤트를 먼저 남기고 커밋 후 즉시 발행합니다. 실패 이벤트만 지수 백오프로 재시도하고 적응형 안전 poll로 유실을 복구합니다.

음성 통화 수명주기

Redis Lua로 1인 1통화와 상태 전이를 원자적으로 제어하고, 세션 연결 해제·TTL·관리자 액션으로 남은 통화를 종료합니다.

운영 가시성

CPU·메모리·디스크·JVM, 접속 상태, outbox·dead letter, 이미지 정리 큐를 표시하고 장애 IP와 반복 횟수를 확인 처리합니다.

Domain Rules

기능을 나열하는 데서 멈추지 않고 정책과 예외 처리를 코드에 반영

Account

상품·정산 정책

입출금·예금·적금별 금리와 만기를 관리하고, 적금 자동이체 및 실패 알림, 해지 시 원금·이자 정산과 거래 취소를 검증합니다.

Safety

신고·제재·상소

중복 신고를 차단하고 경고·일시정지·차단 이력을 남깁니다. 회원은 본인 제재를 선택해 상소하고 관리자는 상태별로 검토합니다.

Audio Call

통화 동시성 제어

1:1 방 참여자만 통화하고, 통화를 시작하거나 받은 기기의 세션만 SDP·ICE·종료 신호를 보낼 수 있도록 검증합니다.

Event Delivery

저장과 전달의 순서

알림과 outbox를 같은 트랜잭션에 저장하고, 채팅은 Consumer의 MySQL 커밋을 마친 결과만 WebSocket으로 전달합니다.

Service Surface

화면, REST API, WebSocket, SSE가 함께 동작하는 서비스 표면
