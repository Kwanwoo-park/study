# 핵심 테스트 구성

기본 검증은 **Java 120건 + JS 45건 = 165건**입니다. JUnit 파라미터별 실행과 JS 페이지별 업로드 사례를 각각 한 건으로 계산합니다.

## 남긴 기준

- 돈·계정·개인 데이터가 잘못 변경되는 오류를 막는 검사.
- 실제 DB 제약·검색 조건·소유권과 트랜잭션 정합성 검사.
- 과거 발생한 토큰 재발급, 모바일 업로드, 알림 재노출, GitHub 페이지 이동 오류의 재발 방지.
- 호출 계층과 전체 Controller/Facade 연결을 확인하는 공통 검사.

단순 위임과 중복 입력 검사는 줄였습니다. 메모의 설정 보존은 실제 설정 저장 흐름에서, DB 저장 결과와 재시도는 같은 영속화 테스트에서 확인합니다.

## 실행

JDK 17, Node.js 22.13 이상을 사용합니다. Java 테스트는 H2, JS 테스트는 Node 기본 모듈과 브라우저/API 더블을 사용하며 실제 Redis/Kafka/S3/메일 서버 없이 실행합니다.

```bash
./gradlew test              # Java + JS
./gradlew build             # 빌드 + 같은 핵심 테스트
./gradlew jsTest            # JS만
./gradlew regressionTest    # test의 호환 별칭, 별도의 중복 실행 없음
```

Node 경로를 직접 지정하려면 `-PnodeExecutable=/절대경로/node`를 추가합니다. PDF의 실제 Chromium 생성 확인은 `node tools/portfolio-pdf/generate.mjs`로 수동 실행하며 기본 테스트에는 포함하지 않습니다.

채팅 복구만 확인하려면 `./gradlew test --tests '*ChatSendFacadeTest' --tests '*ChatRecoveryPersistenceTest'`와 `node --test src/test/js/chat-send-recovery.test.cjs`를 실행합니다. 재시도가 새 메시지·알림 생성을 요청하지 않는 것과 재접속 시 시각·ID 순서를 검사합니다. 이 결과는 실제 Kafka 중단·재기동 시험이나 운영 전달 지연 측정치를 대신하지 않습니다.

새 테스트는 실행 건수를 늘리는 것보다 보호해야 할 동작을 먼저 판단합니다. 같은 조건을 다른 계층이나 입력 값만 바꾸어 반복하는 대신, 새로운 장애 위험을 검증할 때 추가하고 기존 중복 사례를 함께 검토합니다.

## 인프라 통합 테스트

`infrastructureTest`는 실제 MySQL 서버에 임시 스키마를 만들어 마이그레이션 적용과 재적용을 검사합니다. 임시 저장소를 쓰는 Redis를 재시작해 메모 초안과 작업 대기열 보존을 확인합니다. 내장 Kafka 브로커를 중단했다가 재시작해 Outbox가 같은 이벤트 ID로 발행되는지도 검사합니다.

테스트 전용 MySQL 서버의 JDBC 주소와 스키마 생성 권한이 있는 계정을 지정합니다. Redis 실행 파일은 `PATH`의 `redis-server`를 사용합니다. 필요하면 `STUDY_TEST_REDIS_EXECUTABLE`로 경로를 지정합니다.

```bash
STUDY_TEST_MYSQL_URL='jdbc:mysql://127.0.0.1:13306/?useSSL=false&allowPublicKeyRetrieval=true' \
STUDY_TEST_MYSQL_USER=study_test \
./gradlew infrastructureTest
```

비밀번호는 `STUDY_TEST_MYSQL_PASSWORD`로 전달합니다. 테스트 종료 후 임시 MySQL 스키마를 정리하고 Redis와 Kafka를 종료합니다.
